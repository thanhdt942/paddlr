# AGENTS.md — Contributing to Paddlr

This file is for agents and people **developing Paddlr itself**. It is never released.

**First read and follow [rules/AGENTS.md](rules/AGENTS.md).** Those are the Paddlr rules shipped to users, and they bind work in this repository too. The rules below add repository-specific conventions.

## Repository Layout Boundary
- `rules/AGENTS.md`, `rules/CLAUDE.md`: Paddlr rules distributed to users (native packages, plugin `rules/`).
- Root `AGENTS.md`, `CLAUDE.md`: contributor rules for this repository only. Never put repository-specific conventions in `rules/`.
- Project knowledge for this repository lives in `docs/paddlr/` (dev-only, not released).

## Branches & Release
- Work on `dev` (or a branch from `dev`); open pull requests against `dev`.
- Never edit the `release` branch. It is generated by `.github/workflows/release.yml`.

## Verification Before Reporting Done
Run what CI runs (`.github/workflows/ci.yml`), at minimum:

```bash
python scripts/validate_skills.py
python -m unittest discover -s tests
```

## Commit Messages
Use [Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/): `<type>[(scope)][!]: <description>`, e.g. `feat(skills): ...`, `fix(core): ...`, `docs: ...`. Types, scopes, and breaking-change rules: [CONTRIBUTING.md — Commit Message Convention](CONTRIBUTING.md#commit-message-convention). Commit only when the user asks.
