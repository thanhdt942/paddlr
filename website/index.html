Simple on the Surface. Sophisticated Underneath.

Engineering discipline for AI coding agents.

Paddlr is an agent-agnostic software engineering framework that turns proven practices—specs, contract-first plans, TDD, SRE debugging, and persistent project memory—into reusable AI Agent Skills.

Philosophy

Handle the complexity. Simplify the experience.

AI coding agents can write code quickly, but without structure they skip discovery, lose context between sessions, guess at fixes, and claim success without evidence. Paddlr embeds real software engineering discipline into reusable skills so teams get predictable results without memorizing checklists.

Above the Surface

Calm, frictionless developer experience

Invoke one clear slash command or let the agent select the right skill for your task. Every skill has a single, unmistakable purpose and requires zero vendor lock-in.

  • Native plugin manifests for Antigravity, Claude Code, OpenCode, and Codex
  • Automatic session bootstrap via hooks/session-start.py
  • Direct /pdl:* slash commands for every engineering stage
Below the Surface

Disciplined, verifiable engineering rigor

Beneath the simple interface, Paddlr enforces structured discovery, risk-proportional planning, test-first execution, scientific debugging, and Git-tracked project memory.

  • Persistent specs, plans, and immutable ADRs in docs/paddlr/
  • Iron-law TDD (RED → GREEN → REFACTOR) & SRE root-cause analysis
  • Evidence-based verification (PASS / FAIL / BLOCKED) and Git safety guardrails
What Paddlr Is What Paddlr Is Not
A collection of reusable AI Agent Skills conforming to the Agent Skills open standard Not an AI coding agent or LLM runtime itself
A practical Software Engineering Framework backed by rules, hooks, scripts, and tests Not an IDE or closed development environment
A system for applying proven engineering practices with deterministic, checkable artifacts Not an arbitrary collection of ad-hoc prompts
Agent-agnostic by design across Antigravity, Claude Code, OpenCode, and Codex Not tied to a single AI vendor or platform

Workflow

How Paddlr works from intake to verification.

When a session begins, Paddlr loads rules/AGENTS.md and guides your agent through a five-stage engineering loop coordinated by modular skills.

01 / Understand

Inspect & Discover

Inspect Git state, repository structure, conventions, and test commands before editing any file.

scripts/scan_repo.py
02 / Analyze & Plan

Spec & Decompose

Clarify ambiguities, author a reviewable spec, and break work into contract-first slices.

writing-specs → writing-plans
03 / Implement

Incremental Slices

Execute one small, verifiable slice at a time using Red-Green-Refactor TDD cycles.

test-driven-development
04 / Verify

Evidence & Review

Run tests and linters, report concrete PASS/FAIL evidence, and run independent code review.

code-review · sre-debugging
05 / Finalize

Record & Release

Update persistent project context and follow governed semantic release procedures.

docs/paddlr/ · release-management

Level 1 — Small Change

Typo fixes, minor refactors, localized bugs. Lightweight execution with no formal spec or plan overhead.

Level 2 — Feature Development

Multi-component features. Persists a spec in docs/paddlr/specs/ and a fresh plan in docs/paddlr/plans/.

Level 3 — Architectural Change

High-impact trade-offs or breaking changes. Adds an immutable ADR in docs/paddlr/decisions/ with explicit approval.

Quick Start

Up and running in under a minute.

Install Paddlr directly from GitHub in your preferred AI coding agent—no separate runtime or manual copy-pasting required.

1

Prerequisites

Ensure your environment has:

  • Git
  • Python 3.10+ (for lifecycle hooks & repository scripts)
  • One supported agent: Google Antigravity, Claude Code, OpenCode, or OpenAI Codex
2

Install for Your Agent

Install directly via the agy CLI in one command:

bash 
agy plugin install https://github.com/thanhdt942/paddlr

Install inside your Claude Code session via the marketplace or directly from GitHub:

claude-code 
/plugin install paddlr --marketplace thanhdt942/paddlr

Or install directly from the Git repository:

claude-code 
/plugin install thanhdt942/paddlr

Install via the OpenCode CLI (supports both OpenCode v1 and v2):

bash 
opencode plugin add paddlr@git+https://github.com/thanhdt942/paddlr.git

Or declare it in your project's opencode.json (OpenCode v2):

json 
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "paddlr@git+https://github.com/thanhdt942/paddlr.git"
  ]
}

Add the Paddlr marketplace and install the plugin:

bash 
codex plugin marketplace add https://github.com/thanhdt942/paddlr
codex plugin add paddlr
3

First Usage & Expected Output

Start a new agent session in your repository. The SessionStart hook (hooks/session-start.py) automatically injects the Paddlr engineering discipline context. Then invoke any slash command in chat:

chat prompt 
/pdl:feature-development Add rate limiting to the authentication endpoint

On OpenCode, you can also verify the loaded plugin directly from the CLI:

bash 
opencode run "Show me the Paddlr engineering discipline bootstrap context"

Expected bootstrap confirmation in your session:

output 
=== Paddlr Engineering Discipline Active ===
You are operating with the Paddlr software engineering framework.

Project Memory & Configuration

Paddlr persists engineering knowledge canonically inside docs/paddlr/ in your repository so specifications, plans, and architectural decisions stay versioned alongside code instead of disappearing in chat logs.

directory layout 
docs/paddlr/
├── specs/          # Reviewable feature specifications (YYYY-MM-DD-<feature>.md)
├── plans/          # Dedicated contract-first implementation plans per request
├── decisions/      # Granular, immutable Architecture Decision Records (XXXX-<slug>.md)
├── DECISIONS.md    # Lightweight ADR master index
├── PROGRESS.md     # Current operational status and completed slices
└── PLAN.md         # Long-term engineering roadmap

Core operating rules live in rules/AGENTS.md (the authoritative source of truth distributed with the plugin) and rules/CLAUDE.md (the instruction router for Claude Code that imports @AGENTS.md).

Always-new plan rule: Every Level 2 feature and Level 3 architectural change creates a fresh plan file in docs/paddlr/plans/YYYY-MM-DD-<feature>.md. Past plans are never overwritten or appended to.

Slash Commands Reference

Paddlr provides eight slash commands defined in commands/. Each command routes cleanly to its companion Agent Skill.

Slash Command Argument Hint Purpose
/pdl:feature-development [feature idea, requirement, or user story] Orchestrate end-to-end feature delivery across discovery, spec, plan, TDD, and review
/pdl:writing-specs [feature idea or requirements] Clarify requirements and author a reviewable specification in docs/paddlr/specs/
/pdl:writing-plans [spec path or feature description] Decompose a spec into bite-sized, contract-first tasks in docs/paddlr/plans/
/pdl:test-driven-development [task or behavior to implement] Implement features or bugfixes strictly test-first (RED → GREEN → REFACTOR)
/pdl:sre-debugging [error message, failing test, or symptom] Run evidence-based root-cause analysis before proposing or applying fixes
/pdl:code-review [commit range, task, or files to review] Perform independent, read-only code review against specifications and quality standards
/pdl:release-management [release type, version bump, or stage] Manage semantic releases and persist project release conventions in RELEASE.md
/pdl:skill-creator [skill idea, workflow, or skill to audit] Design, draft, verify, and package new reusable AI Agent Skills

Agent Skills Architecture

Each skill resides in skills/<skill-name>/SKILL.md with YAML frontmatter (name, description) and optional references/ files loaded progressively only when needed.

  • feature-development — Six-phase orchestrator (Intake, Workflow Triage, Spec/Plan, Implementation, Verification/Review, Completion Gate) that delegates to companion skills without duplicating their internals.
  • writing-specs — Clarifies scope, edge cases, acceptance criteria, and ADR gates (references/adr-guide.md) before implementation planning.
  • writing-plans — Produces ordered, contract-first task checklists (Consumes / Produces) with explicit verification steps.
  • test-driven-development — Enforces writing a failing test first, implementing minimal code to pass, and refactoring cleanly.
  • sre-debugging — Combines Google SRE Effective Troubleshooting and Zeller's Scientific Debugging to isolate root causes before editing code.
  • code-review — Independent verification of correctness, spec alignment, security, and maintainability prior to merging.
  • release-management — Governs versioning, changelogs, release validation gates, and post-release verification.
  • skill-creator — Guides authoring and auditing new platform-agnostic skills using progressive disclosure.

OpenCode Tools & Lifecycle Hooks

When installed in OpenCode (index.js), Paddlr registers three tools and three lifecycle hooks natively. Legacy hsiw_* tool aliases remain supported for backward compatibility.

Name Type Behavior
pdl_bootstrap Tool Returns the full Paddlr engineering discipline context and skill catalog
pdl_status Tool Inspects docs/paddlr/ memory files (PROGRESS.md, PLAN.md, DECISIONS.md, PROJECT.md)
pdl_scan Tool Invokes scripts/scan_repo.py --json to inspect repository structure and tech stacks
session.created Hook Logs activation confirming Paddlr discipline is active for the session
experimental.chat.system.transform Hook Injects BOOTSTRAP_CONTEXT into the agent's system prompt
tool.execute.before Safety Hook Blocks unconfirmed destructive Git commands (git reset --hard, git clean -fd, git push --force)

SessionStart Hook (Antigravity & Claude Code)

hooks/session-start.py automatically detects the calling environment and emits either the Google Antigravity injectSteps payload or the Claude Code / Cursor / Gemini CLI hookSpecificOutput payload.

Utility Scripts & Verification

Paddlr ships dependency-free Python scripts used both during repository discovery and in CI quality gates (Python 3.10+):

bash 
# Scan any repository safely (flags .env/keys without reading contents)
python scripts/scan_repo.py . --depth 3

# Output machine-readable JSON scan report
python scripts/scan_repo.py . --json

# Validate all skills against the Agent Skills open standard
python scripts/validate_skills.py --verbose

# Run the full automated unit & plugin conformance test suite
python -m unittest discover -s tests -v

# Verify internal Markdown links resolve without broken references
python scripts/check_markdown_links.py

Customization & Authoring Skills

You can extend Paddlr for your team's domain workflows without forking the framework:

  • Author new skills: Run /pdl:skill-creator to draft a standard SKILL.md with progressive disclosure and verify it with python scripts/validate_skills.py.
  • Local OpenCode plugin linking: For offline or custom local development, clone the repository and export index.js from .opencode/plugins/paddlr.js:
javascript (.opencode/plugins/paddlr.js) 
export { default } from "./path/to/paddlr/index.js";

Troubleshooting

  • OpenCode v1 vs. v2 configuration key: OpenCode v2 uses "plugins": [...] (plural) in opencode.json, whereas OpenCode v1 uses "plugin": [...] (singular). Paddlr's index.js supports both runtime loaders automatically.
  • SessionStart hook does not run: Confirm Python 3.10+ is available in your PATH. On Windows, hooks/run-hook.cmd wraps Python execution for cross-platform compatibility.
  • Destructive Git command blocked: In OpenCode, tool.execute.before intentionally blocks git reset --hard, git clean -fd, and git push --force unless explicitly run by the user outside the agent guardrail.
  • pdl_status reports repository not initialized: Create docs/paddlr/ (or run /pdl:writing-specs / /pdl:feature-development) to initialize persistent project memory files.
FAQ

Frequently asked questions.

Does Paddlr replace my AI coding agent or IDE?

No. Paddlr is not an AI coding agent or IDE. It is an agent-agnostic plugin and skill framework that runs inside the agent you already use—Google Antigravity, Claude Code, OpenCode, or OpenAI Codex.

Do I have to write a full specification and plan for a small bug fix?

No. Paddlr uses proportional overhead defined in rules/AGENTS.md. Small, localized fixes (Level 1) skip formal specs and plans; Level 2 features persist a spec and plan in docs/paddlr/; Level 3 architectural changes add an ADR and explicit approval gate.

Does scripts/scan_repo.py read my .env files or secrets?

No. scan_repo.py explicitly matches sensitive filenames (.env*, *credential*, *secret*, *token*, *.pem, *.key, SSH keys) and flags them by filename only without ever reading or printing their contents.

How does Paddlr keep plans from getting lost between sessions?

Instead of leaving plans inside ephemeral chat threads, Paddlr stores specifications in docs/paddlr/specs/, a dedicated implementation plan per request in docs/paddlr/plans/, and immutable ADRs in docs/paddlr/decisions/—all plain Markdown tracked in Git.

How can I contribute or add a new skill to Paddlr?

Work on the dev branch (never edit the release branch directly), follow Conventional Commits, and verify your changes with python scripts/validate_skills.py, python -m unittest discover -s tests, and python scripts/check_markdown_links.py before opening a pull request.
